# 展示站点计划

> 最后更新：2026-10-28 ｜ 归属 ROADMAP 阶段 U6.1（用户流程）与 U6.2（查看页）

## 目的

用一个小网站讲清楚这个项目：**问题是什么、怎么修的、效果如何、证据在哪**，并能**现场发起一次综述**，看着 Agent 检索、读全文、登记证据、过关卡。

- 读者：面试官、评审、想了解项目的人。
- 核心功能：在线综述。输入主题，实时看到每个阶段，结束后得到经过核查的报告。
- 数据：浏览部分只读 `runs/` 里已有的结果，不产生费用；在线综述调用本机 DeerFlow，每次约 50–200 万 token（实测范围）。
- 数字从结果文件实时计算，不在前端写死。
- 如实标注版本：v3 是历史正式结果，v5（全文证据）仍在开发。

## 范围

| 做 | 不做（本轮） |
|---|---|
| 在线综述：发起、实时进度、取消、结果核查 | 账号、权限、部署到公网 |
| 项目概览、实验结果、单次运行详情、方法与局限 | 修改 DeerFlow 或插件代码 |
| 报告阅读、引用核查、关卡记录、证据追溯；本机一条命令启动 | 同时跑多个任务 |

## 技术选型

- **后端**：FastAPI，只读 `runs/` 中已入库的小文件（meta、citations、gate、claims、evidence、summary），不读体积大的原始 trace。套件和运行名必须是已有目录，防止越权读取。
- **前端**：Vite + React + TypeScript；Markdown 用 `react-markdown`。
- **风格（Claude 风格）**：暖白底色、陶土橙强调色、标题用衬线字体、正文无衬线；留白多、圆角、细边框，少阴影。只做浅色主题。

## 页面

1. **概览**：一句话定位 → 关键结果（上游 vs v3）→ 同一主题的两份报告 → 问题 / 根因 / 做法 → 修复前后的数据流。
2. **实验**：全部评测套件，按留出 / 开发 / 冒烟 / 失败归档分组；点开看每次运行。
3. **运行详情**：报告、引用核查、论断评判、关卡记录、原文证据。v5 报告中的 `[E#]` 可点击，查看原文引语和出处。可导出 BibTeX（只含已通过核查的引用）和证据 CSV。
4. **方法与局限**：评测流程、指标、版本、需要如实说明的限制。

## 在线综述（核心功能）

**流程**：填写主题 → 后端调用本机 DeerFlow → 页面实时显示阶段 → 结束后自动核查引用 → 生成与历史运行同样的详情页。

| 阶段 | 判断依据 |
|---|---|
| 读取方法 | 主 Agent 读取 Skill |
| 检索 | 调用 `search`，返回候选论文 |
| 筛选 | 调用 `screen`，确定入选论文 |
| 阅读全文 | 子 Agent（`task`）运行中；插件写入的 `evidence.jsonl` 实时增长 |
| 汇总证据 | 调用 `evidence_index` |
| 撰写报告 | 调用 `write_file` |
| 关卡核查 | 调用 `present_files`，插件在 `gate.jsonl` 写入通过 / 拒收 |
| 引用核查 | 运行结束后，后端对照 arXiv API 逐条核对 |

**设计要点**

- 后端持有与 DeerFlow 的事件流（DeerFlow 在流断开时会取消运行），浏览器每秒轮询后端。刷新页面不影响任务。
- 同一时间只跑一个任务；可以取消（调用 DeerFlow 的 cancel 接口）。
- 提示词与评测相同（`eval/` 的格式），保证行为与评测结果可比；模型固定 `qwen3.5-plus`。
- 发起任务的请求需带自定义请求头，防止其他网页借浏览器在本机发起付费任务。
- 结果存入 `runs/suite-live/<任务 ID>/`，文件结构与评测运行相同，因此可直接复用详情页。该目录不入库。
- 使用的是当前部署的插件与 Skill（开发中的 v5），页面上标明这一点。

## 运行方式

在线综述需要本机 DeerFlow 在运行（`http://localhost:2026`），并且 `.local/cookies.txt` 里有登录会话；与 `eval/run_task.py` 的要求相同。新建页会显示连接状态，未就绪时不能提交。

需要 Python 3.10+ 和 Node 20+。在仓库根目录：

```bash
showcase/start.sh          # 首次会安装依赖；打开 http://127.0.0.1:8787
```

开发时前后端分开跑（前端热更新，`/api` 自动转发到 8787）：

```bash
cd showcase/backend && .venv/bin/uvicorn app:app --port 8787 --reload
cd showcase/frontend && npm run dev
```

检查：

```bash
showcase/backend/.venv/bin/python -m pytest -q showcase/backend/tests
cd showcase/frontend && npx oxlint src && npm run build
```

## 口径说明

数字与 README 采用同一口径，避免展示站点自成一套：

| 数字 | 来源 |
|---|---|
| 达标运行、Wilson 区间 | 复用 `eval/holdout_report.py` 的 `clean()`、`wilson()` |
| 引用已验证 / 窗口 / 类别比例 | 交付报告中的引用为分母，同 `eval/aggregate.py` |
| 半数以上编造 | `verified ≤ refs / 2`，同 `aggregate.py` |
| 关卡结论 | 只取 accepted / rejected / released_unverified，同 `aggregate.py` |
| 论断有依据 | v2 评判器逐运行计算，同 `claims.py summary`。`runs/claims-holdout3-summary.json` 是旧 v1 结果，不使用 |
| token | DeerFlow 运行记录（`runs/token-run-record-20261027.json`），缺失时依次退回事件流、最终状态 |

## 设计取舍

- 主结果用数字卡片；各项指标的「上游 vs v3」用哑铃图。配色经 dataviz 校验：灰 `#5e5d59` / 橙 `#c15f3c`，区分度与对比度通过（灰色饱和度低是弱化色的本意）。图表附表格视图，两组都有直接标注。
- 状态颜色都配文字（如「● 通过」），不单靠颜色区分。
- 构建后由后端一个进程同时托管页面和 API，演示时只需一条命令。

## 已知限制 / 后续

- 论文标题和 BibTeX 元数据优先取运行自带的 `search.json`，没有时取引用核查器的缓存 `eval/.arxiv_cache.json`（已入库）。只有已验证的引用才显示标题：未通过核查的编号即使在 arXiv 上存在，对应的也是别的论文。
- 「达标」只看引用；v5 关卡还核对证据标记，所以 v5 会出现「达标但关卡拒收」，套件页有说明。
- 「方法与局限」页的文字说明是静态的，与 README 同步维护；页面上的数字都来自 API。
